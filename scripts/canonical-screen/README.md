# Canonical authored screen workload

Original Atlas dataset-review interface and fictional observation data authored for EncodingDB. This is a browser-rendered screen-content reference, not natural camera footage or a test-pattern substitute. The page uses local assets only. All authored HTML, capture code and resulting screen images/video in this directory's workflow are dedicated under CC0 1.0: https://creativecommons.org/publicdomain/zero/1.0/ . No endorsement or real dataset is represented.

IBM Plex Mono Regular is separately licensed under SIL Open Font License 1.1 (see `fonts/OFL.txt`). Font source: google/fonts commit `142c8963e7606b510c93a644c82a4c4cdeae6ef9`, `ofl/ibmplexmono/IBMPlexMono-Regular.ttf`; downloaded from the corresponding immutable raw.githubusercontent.com URL. The font file is checked in to permit offline capture.

Run `node scripts/capture_canonical_screen.mjs`. Set `PLAYWRIGHT_MODULE` to an existing Playwright 1.62.1 `index.mjs` and optionally `CHROMIUM_EXECUTABLE` to Chromium headless shell 151.0.7922.34. The media tools default to repository-pinned `client/bin/mac/ffmpeg` and `client/bin/mac/ffprobe`; `FFMPEG` and `FFPROBE` may explicitly override these paths and their hashes are retained. `--encode-only` reuses the 240 PNGs only after matching every retained frame hash. No repository dependency installation is required. Default paths use the Codex bundled runtime and Playwright browser cache on macOS ARM64. The script refuses other browser/Playwright versions. Metadata records executable and input hashes, platform, flags and full commands; rendering across OS/font rasterizers is not asserted bit-identical.

240 lossless PNG frames are sampled at exact frame-index times (0..239 at 24 fps), 1920×1080, device scale 1. Animation is explicit; there are no wall-clock events or network assets. The workload begins with a stationary document, scrolls source at seconds 2–5 and table at seconds 5–8, then selects a row while the cursor continues moving. Navigation, summary cards and footer geometry remain static. The RGB PNGs undergo explicit sRGB transfer to BT.709 transfer/primaries/matrix conversion with limited-range output using zscale, then are encoded to FFV1 level 3 YUV420P 8-bit, BT.709 limited-range SDR; full decode and frame-count assertions must pass. This is intentionally SDR browser source, with no HDR metadata.

Outputs under `.build/canonical-screen/` include frames, screen-workload.mkv, full-decode.log, ffprobe.json, metadata.json and contact-sheet.png. The integration owner must promote the verified video/metadata into the canonical suite and publish durable artifacts; `.build` alone is not a deliverable. Visual acceptance is a separate human/Codex inspection, never implied by a successful capture.
