# Predeclared hardware duration extension

The original 42 software cells and their outcomes stay unchanged. The separate hardware extension contains 28 cells: seven registered 30-second sources at native VBR targets 4000 and 8000 kbps for P910 h264_nvenc/p4 and Mac h264_videotoolbox/default. Targets describe requested rate control, not achieved bitrate or equal perceptual quality. Protocol stability and validity gates remain unchanged; failed or unsupported cells remain failures.

Before timing, bind the clean integrated source commit/archive and locked runtime to the execution receipt. The NVENC shared command builder must emit explicit `-rc vbr -b:v`; selecting a target must never silently choose CQ, QP or a software encoder. The existing canonical device-0 selection remains in the canonical encode launcher. Record actual timing, output and failures through the same runner, warmup, adaptive repetition and cancellation boundaries.

P910 can read registered references in place. Mac stages only one registered source at a time at the exact path declared in `timing-hardware-extension-v1.json`, checks its SHA/size, uses the parent's canonical state directory, and preserves at least 5 GiB free. A hardware invocation adds `--target-bitrate-kbps 4000` (or 8000) and omits `--crf`. No file acquisition, upload, import, analysis or build runs concurrently with native timing on that host.

For later P910 import, preserve the complete Mac receipt unchanged. `mac-reference-path-bindings-v1.json` maps its exact staged reference path to the original registered P910 file with the same SHA. Copy encoded bytes into owned P910 storage and add one `ENCODED` binding per counted attempt, recording `originalPath` exactly from its original journal, `sha256` from that journal and absolute `retainedPath` of the copied object. Pass the complete mapping to the importer with `--path-bindings`. The importer rejects ambiguous or hash-substituted mappings, verifies actual file hashes, preserves original paths/raw records, and records the mapping hash and retained paths separately. Neither workload IDs, source hashes, native recipes nor original evidence are rewritten.

The extension can establish duration/GOP/startup sensitivity for these available hardware paths only. Human quality judgments, held-out ranking acceptance and reviewed PL activation remain separate outstanding gates.
